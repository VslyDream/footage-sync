## FUT-001 — Маркеры исходного клипа из файла

### Цель и желаемое поведение

[LOCKED — future intent]

Автоматически добавлять маркеры на **конкретный исходный клип / футаж (`ClipProjectItem`)** Premiere из внешнего файла с данными. Решение пользователя 2026-10-03 заменяет первоначальный target секвенции. Если clip markers подтверждённо невозможны, остановиться и уточнить решение; sequence markers не являются fallback. Референс формата и цифровой кодировки цветов — **Markerbox**.

Нужны оба способа указания источника:

1. **Ручной:** пользователь выбирает конкретный файл с маркерами для media. Возможность нужна как при импорте, так и для уже существующих файлов.
2. **Автоматический:** опция поиска TXT в той же папке, что и media, с идентичным или очень похожим именем.

Основной UI-сигнал: при импорте **рядом с названием media показывать иконку**, если автоматически найден TXT с маркерами. Обнаружение файла и фактическое добавление маркеров — отдельные события; применение вместе с Sync после импорта media.

### Пример пользователя

```text
D:\2_Library\Video\2026-09-30\converted\Vasiliy_2026-09-30-12-16-56.txt
D:\2_Library\Video\2026-09-30\converted\Vasiliy_2026-09-30-12-16-56_repack.mp4
```

[LOCKED — future intent] Пара выше должна учитываться при проектировании matching: TXT не имеет суффикса `_repack`, который присутствует у видео. [LOCKED — 2026-10-03] Полный basename TXT включён в basename MP4; правило охватывает _repack и другие префиксы/суффиксы.

[VALIDATED — local file read, 2026-10-02] Указанный TXT доступен; в нём семь строк без заголовка:

```text
0:00:53,1
0:01:12,1
0:01:30,1
0:01:52,1
0:03:34,1
0:04:06,1
0:04:27,1
```

Формат первой версии: `H:MM:SS,colorIndex`, разделитель — запятая, целые секунды от начала исходного видео. Дробные секунды и frame timecode не поддерживаются. Этот пример не доказывает поддержку всех форматов Markerbox.

### Цвета

[LOCKED — future intent] Использовать то же соответствие цифр цветам, что в Markerbox.

[VALIDATED — installed Markerbox 0.8.2 source] В `js/default-settings.js:21` установленного плагина указаны восемь индексов **0–7**. В `jsx/Premiere.jsx`, функция `create_markers`, числовой индекс передаётся в `setColorByIndex` без перенумерации.

| Цифра | Цвет по Markerbox | Описание для ориентира |
|---|---|---|
| 0 | green | Зелёный |
| 1 | red | Красный |
| 2 | rose | Розовый / фиолетовый оттенок Premiere |
| 3 | orange | Оранжевый |
| 4 | yellow | Жёлтый |
| 5 | white | Белый |
| 6 | blue | Синий |
| 7 | teal | Бирюзовый / cyan |

В приведённом TXT все строки имеют индекс `1` — красный. [VALIDATED — local host, 2026-10-03] Все восемь индексов установлены и прочитаны обратно на source clip в Premiere 25.6.2; evidence: `artifacts/marker-host-test/spike-result.json`.

### Принятые правила первой реализации

[LOCKED — user confirmation, 2026-10-03]

Полный контракт перенесён в SPEC.md §16. Время от начала исходного видео; двухколоночный TXT и цвета 0–7. Автопоиск ON по умолчанию: тот же каталог, полный basename TXT является подстрокой basename MP4. Ручной выбор имеет приоритет; несколько кандидатов требуют выбора. Применение после импорта media во время Sync.

Повторный обычный Sync пропускает последнюю обработанную версию TXT. Изменения/повторный ручной выбор: Replace markers / Add to existing / Skip TXT. Replace включает ручные маркеры этого source item, с явным предупреждением. Неверный/недоступный TXT пропускается целиком до исправления с конкретным предупреждением; импорт видео продолжается.

Ручной выбор: строка media в Initial Sync / Review, кнопка и ПКМ; существующие media в Status. Индикация найденного TXT рядом с media, отдельное состояние применения. Расширение экранов отражено в UI_SPEC; Main Panel сохраняется.

[VALIDATED — local Premiere 25.6.2]

Первая версия интегрирована в scanner/controller/UI. Source markers, цвета, относительное video timing, AUTO/manual Sync, повтор без дублей и recovery/reopen проверены на generated fixtures в 25.6.2. Private project metadata хранит receipts; пользовательский project не сохраняется автоматически. Native Undo не гарантирует rollback source markers; Premiere XMP preference может разрешать запись в media. Полная release acceptance и решения по этим ограничениям остаются открытыми. Результаты — [STATE.md](../STATE.md) и [local acceptance](../artifacts/marker-host-test/ACCEPTANCE.md).

## FUT-002 — Компактные кнопки / вертикальная панель

### Цель и порядок вариантов

[LOCKED — future intent]

Занимать меньше места в workspace Premiere при сохранении удобного доступа к основным действиям плагина.

1. **Предпочтительный вариант для исследования:** добавить кнопки плагина во встроенное окно **Tools** Premiere, рядом с Selection Tool, Type Tool и другими инструментами.
2. **Запасной вариант:** если Tools недоступен или требует ненадёжного обходного решения, сделать собственную очень узкую вертикальную панель с маленькими иконками и корректным масштабированием.

Ориентир пользователя для второго варианта — колонка примерно **50 px шириной × 250 px высотой**. Это желаемый размер, не подтверждённый минимум host. Кнопки должны сохранять корректный вид и доступность при таком уменьшении окна.

Для вертикального варианта отдельно исследовать возможность **скрыть название окна / верхнюю шапку**, чтобы приблизить компактность к встроенной Tools panel.

### Связь с текущим UI

Три действия Links / Sync / Status и их flows сохранены. Прежний width target 320–360 px и композиция с header/подписями заменены принятым adaptive contract ниже. FUT-002 меняет только Main Panel; остальные screens по-прежнему открываются в отдельных окнах.

### Принятые уточнения — 2026-10-06

[LOCKED — user decision]

- Одна панель автоматически переключается между вертикальным и горизонтальным видом по порогу доступной ширины.
- 50 × 250 px — ориентир. Считывать фактическую ширину колонки; масштабировать иконки, отступы и кнопки, предпочтительно избегая прокрутки при недостатке места.
- Постоянных подписей нет в обоих видах; названия доступны в подсказках.
- Желательно скрыть обе шапки. Собственная удаляется; native Premiere header допустимо сохранить, если поддерживаемого способа скрытия нет.
- Status показывает число изменений, attention остаётся различимым. Работающий Sync обозначается анимацией, предпочтительно кружком/spinner; точный rendering делегирован.
- Рабочее окружение: 2K + Full HD мониторы, преимущественно docked. Вертикальный вид нужен для максимально компактного закрепления. Windows scaling percentages не указаны.
- Точный threshold, icon/hit-area bounds и достижимый host minimum определить проверкой; отсутствие подтверждения Tools API не блокирует согласованный вариант собственной панели.

Contract обновлён в SPEC §10/§15.1 и UI_SPEC UI-01. Старый Main Panel PNG сохранён как предыдущая композиция и не задаёт новый target; новые runtime references предоставлены в docs/ui. Остальные PNG сохраняют существующую роль.

### Результаты первоначального исследования

[VALIDATED — official documentation] UXP описывает entrypoints `command` и `panel`. Panels могут docking/resizing; команды появляются в Window > UXP Plugins: [Panels and Commands](https://developer.adobe.com/premiere-pro/uxp/plugins/concepts/panels-and-commands/).

[OPEN / SPIKE] В просмотренных официальных страницах не найден документированный способ добавлять кнопки именно во встроенную Tools panel или скрывать host header своей dockable panel. Это **не доказательство невозможности**. Нужен адресный поиск и, при недостатке документации, минимальная проверка в целевой версии Premiere.

[VALIDATED — official documentation] Manifest имеет `minimumSize` / `maximumSize`, но Adobe оговаривает, что host может не соблюдать эти размеры. Значение `species: ["toolbar"]` описывает назначение ресурса иконки; само по себе оно не подтверждает размещение кнопки в Tools: [Plugin manifest](https://developer.adobe.com/premiere-pro/uxp/plugins/concepts/manifest/).
