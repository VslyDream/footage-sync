## FUT-003 — MCP для управления Footage Sync

### Назначение и команды

Дать ChatGPT/Codex и Claude Desktop доступ к тем же данным и действиям, которые доступны человеку в плагине:

- Просматривать выбранные import project/sequence, links, файлы, изменения, проблемы, историю и ход Sync.
- Добавлять folder ↔ bin links с Initial Sync preview и удалять links (не папки с диска и не media из Premiere).
- Добавлять файлы/папки в постоянный Ignore, просматривать правила и делать Restore.
- Запускать Sync с добавлением новых видео на timeline либо только импортом файлов.
- Получать структурированный Review с допустимыми решениями, выбирать/откладывать/игнорировать изменения и применять пакет по существующим правилам.

UI и MCP должны использовать общий Controller/command-state слой: один scanner/planner, одинаковые блокировки, проверка актуальности проекта/плана, защита от повторного выполнения и сериализация изменений между UI и несколькими AI-клиентами. Большие списки выдаются порциями; запрос статуса не запускает дополнительный полный scan.

### Выбранный пользовательский vision

[LOCKED — future intent] MCP включён по умолчанию; выключатель находится в Settings и нужен на случай явного отключения. Пользователь не запускает отдельную программу вручную, не держит tray-приложение и не обслуживает адаптер. Отсутствие адаптера — штатное тихое ожидание без ошибок/уведомлений. При появлении адаптера плагин подключается автоматически; после обрыва восстанавливает соединение. Выключенная настройка прекращает соединение и попытки подключения со стороны плагина.

Первоначальное подключение в AI-приложении отделено от ежедневного использования. [OPEN] Упаковка адаптера, автоматизация регистрации в каждом клиенте и permission UX требуют отдельного решения/проверки; отсутствие ручного запуска не означает отсутствие первоначальной настройки.

### Предлагаемая архитектура и границы

[SPIKE] Локальный MCP-адаптер: AI desktop client ↔ MCP stdio ↔ adapter process ↔ authenticated loopback WebSocket ↔ UXP plugin. Это кандидат реализации, не проверенная интеграция. Адаптер поставляется вместе с интеграцией и запускается локальным MCP-клиентом по зарегистрированной команде. Облачная модель сама процесс не запускает; тег инструмента в чате не гарантирует запуск именно в этот момент. Клиент может держать процесс всю MCP-сессию. Завершение при закрытии канала, полном выходе клиента, аварии и нескольких чатах нужно проверить отдельно. Выключатель в Premiere отключает доступ, но не обещает завершить процесс, которым управляет другой клиент.

Пока адаптер отсутствует, кандидат — редкие подключения с увеличением интервала повторов; после соединения — обработка сообщений по событиям. Интервалы не зафиксированы: выбрать по замерам нагрузки и задержки обнаружения. Включение по умолчанию не означает открытый доступ любому локальному процессу; нужна проверка нашего адаптера без ручной настройки секрета пользователем.

[VALIDATED — documentation only, 2026-11-06] [OpenAI desktop/Codex MCP](https://learn.chatgpt.com/docs/extend/mcp), [Claude Desktop local MCP](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop), [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) и [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) описывают локальные подключения. [Adobe network recipe](https://developer.adobe.com/premiere-pro/uxp/resources/recipes/network/) документирует клиентский WebSocket на baseline 25.6/manifest 5 с network permission. Это не native acceptance нашего адаптера и не обещание совместимости с web/cloud chats. Нынешний manifest имеет только filesystem fullAccess; готового bundled helper нет. Hybrid C++ вариант требует 26.2+ и не выбран как основание повышать baseline.

### Обязательная проверка производительности перед принятием реализации

[LOCKED — user requirement] Нельзя объявлять MCP бесплатным по ресурсам или незаметным без численных замеров. **Обязательно измерить абсолютное потребление ресурсов при выключенном MCP**, а также сравнить с исходной сборкой без MCP. Отдельно измерять Premiere/UXP (насколько позволяет profiling) и процессы адаптера, чтобы расходы внешнего процесса не скрывались в оценке.

После отдельного разрешения на работу выполнить одинаковые воспроизводимые сценарии:

1. Исходная сборка без MCP — контрольный baseline.
2. Сборка с MCP, настройка выключена — CPU, память, I/O и отсутствие подключения/retry timers; отдельно учитывать адаптер, если AI-клиент его оставил запущенным.
3. MCP включён, адаптер отсутствует — стоимость попыток, их частота, длительный idle.
4. Адаптер подключён без команд — CPU/RAM обоих участников и обслуживание соединения.
5. Status/Review, большие списки и Sync через MCP — задержки, I/O, влияние на отзывчивость UI и playback; сравнение с тем же Sync через UI.
6. Запуск/закрытие клиента, reconnect, несколько клиентов, закрытая панель и длительная работа — задержка обнаружения, утечки, оставшиеся процессы.

Фиксировать версии/машину/проект, длительность, CPU (среднее и пики), RAM, disk/network I/O, размер пакета и зависимости; сравнивать абсолютные значения и разницу с baseline. Точные допустимые пороги пока [OPEN]; лёгкость интеграции должна подтверждаться результатами, включая выключенное состояние. macOS и разные способы установки требуют отдельных проверок.

## FUT-001 — Маркеры исходного клипа из файла

### Цель и желаемое поведение

[LOCKED — future intent]

Автоматически добавлять маркеры на **конкретный исходный клип / футаж (`ClipProjectItem`)** Premiere из внешнего файла с данными. Решение пользователя 2026-10-03 заменяет первоначальный target секвенции. Если clip markers подтверждённо невозможны, остановиться и уточнить решение; sequence markers не являются fallback. Референс формата и цифровой кодировки цветов — **Markerbox**.

Нужны оба способа указания источника:

1. **Ручной:** пользователь выбирает конкретный файл с маркерами для media. Возможность нужна как при импорте, так и для уже существующих файлов.
2. **Автоматический:** опция поиска TXT в той же папке, что и media, с идентичным или очень похожим именем.

Основной UI-сигнал: при импорте **рядом с названием media показывать иконку**, если автоматически найден TXT с маркерами. Обнаружение файла и фактическое добавление маркеров — отдельные события; применение вместе с Sync после импорта media.

### Пример пользователя

```text
D:\2_Library\Video\2026-09-30\converted\Vasiliy_2026-09-30-12-16-56.txt
D:\2_Library\Video\2026-09-30\converted\Vasiliy_2026-09-30-12-16-56_repack.mp4
```

[LOCKED — future intent] Пара выше должна учитываться при проектировании matching: TXT не имеет суффикса `_repack`, который присутствует у видео. [LOCKED — 2026-10-03] Полный basename TXT включён в basename MP4; правило охватывает _repack и другие префиксы/суффиксы.

[VALIDATED — local file read, 2026-10-02] Указанный TXT доступен; в нём семь строк без заголовка:

```text
0:00:53,1
0:01:12,1
0:01:30,1
0:01:52,1
0:03:34,1
0:04:06,1
0:04:27,1
```

Формат первой версии: `H:MM:SS,colorIndex`, разделитель — запятая, целые секунды от начала исходного видео. Дробные секунды и frame timecode не поддерживаются. Этот пример не доказывает поддержку всех форматов Markerbox.

### Принятые правила первой реализации

[LOCKED — user confirmation, 2026-10-03]

Ручной выбор: строка media в Initial Sync / Review, кнопка и ПКМ; существующие media в Status. Индикация найденного TXT рядом с media, отдельное состояние применения. Расширение экранов отражено в UI_SPEC; Main Panel сохраняется.
